# 2026-07-20 任务报告

## 完成结果

本次完成“论文阅读”和“格式审查”两条业务线的落地、配置和真实 UMAP 验证。

- 阅读：用户 PDF 经 MinerU、百度专项 OCR 和 `second_clean` 后，Block、媒体对象和 Chunk 均写入 PostgreSQL；阅读检索只读用户有权限的本地 `PaperChunk`，不会导入或检索用户论文的 RAGFlow 知识库。
- 格式审查：前端只提交 `paper_id`、`format_profile_id` 和规则 ID。服务端冻结 Profile、规则和 RAGFlow 数据集映射，按规则持久化论文证据、规范证据、页码、严重级别和建议。
- Web 上传：后端已改为复用已验证的 MinerU v4 与百度专项 OCR 适配层，修复了原先“密钥已配置但 Web 端调用不存在的简化端点”的问题。
- 配置：已写入后端和用户论文流水线的 MinerU、百度 OCR、RAGFlow 密钥；已创建前端 `.env`（只含 API 地址）。报告不包含任何密钥明文。
- 依赖：后端声明并安装 `requests`，用于复用 MinerU/百度 OCR 官方 HTTP 流程。
- 前端入库状态：进度条已与实际流程统一为“接收 → 版面解析 → 内容补全 → 二次清洗 → 入库校验 → 论文理解 → 可阅读”。当生成模型不可用时，`ready + understanding.status=unavailable` 明确表示“可检索和阅读、摘要暂不可用”；失败卡显示失败阶段、错误编号和可重试提示，不再用“论文入库失败，请稍后重试”的泛化文案掩盖状态。
