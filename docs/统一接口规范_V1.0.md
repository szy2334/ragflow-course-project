# 科研论文智能阅读与格式审查系统统一接口规范

> 版本：V1.1
> 状态：开发基线
> 依据：[需求文档 V2.1](./7.18/多智能体论文问答与评审系统_需求文档_v2.md) 与 [详细设计文档 V1.2](./7.18/多智能体论文问答与评审系统_详细设计文档_V1.1_实施验证修订版.md)

## 1. 目的与边界

本规范只定义跨边界契约：前端与后端 API、业务模块之间的命令/结果、异步事件与外部服务适配边界。模块内部的控制器、仓储、提示词、模型参数和实现细节不属于本规范。

详细设计文档优先。本规范对其中未固定的 URL、异步返回形式和命名进行收敛，作为后端 OpenAPI 与前端 `src/api` 的唯一实现依据。

| 边界 | 调用方 | 提供方 | 约束 |
| --- | --- | --- | --- |
| 用户界面 | 前端 | 后端 API | 前端只提交业务资源 ID；不得提交 `user_id`、RAGFlow `dataset_id` 或 `document_id`。 |
| 任务编排 | chat / paper | LangGraph / task worker | 命令立即受理，耗时结果通过任务查询或 SSE 返回。 |
| 阅读检索 | reading workflow | local chunk store | 只从用户已授权论文的本地结构化片段取证；不调用 RAGFlow 规范库。 |
| 格式规范检索 | format review worker | RAGFlow | 客户端只提交 `format_profile_id`；服务端从冻结的格式规范快照映射数据集和规则。 |
| 文档处理 | paper | parser / ocr / chunking / understanding agent | 各阶段只交换已标准化的任务上下文和结果摘要，用户 PDF 不导入知识库。 |
| 结果输出 | reading workflow / format review | session / review report | 阅读只持久化理解性回答；格式审查持久化规则级合规结论和两类证据。 |

## 2. 统一约定

### 2.1 传输、版本与鉴权

- 基础路径为 `/api/v1`，JSON 使用 UTF-8，字段采用 `snake_case`。
- 登录后的请求携带 `Authorization: Bearer <access_token>`；刷新令牌仅由 `HttpOnly` Cookie 传递。
- 前端为每个写请求生成 `X-Request-Id`；异步创建、重试、取消和导出请求还必须携带 `Idempotency-Key`。
- 服务端从令牌取得 `user_id` 和 `role`，忽略客户端伪造的同名字段。
- `GET` 列表统一采用 `page`、`page_size`、`sort_by`、`sort_order`；最大页大小由服务端限制。

### 2.2 响应包络与分页

除二进制下载和 SSE 外，成功响应使用以下包络：

```json
{
  "code": "ok",
  "message": "",
  "data": {},
  "request_id": "uuid",
  "timestamp": "2026-07-19T09:00:00Z"
}
```

分页的 `data` 为：

```json
{ "page": 1, "page_size": 50, "total": 120, "items": [] }
```

失败响应不返回内部堆栈：

```json
{
  "code": "PAPER_NOT_READY",
  "message": "论文尚未完成解析和理解。",
  "details": { "paper_id": "uuid", "status": "understanding" },
  "request_id": "uuid",
  "timestamp": "2026-07-19T09:00:00Z"
}
```

### 2.3 公共枚举

| 名称 | 取值 |
| --- | --- |
| `task_status` | `pending`、`running`、`succeeded`、`failed`、`cancelled` |
| `paper_status` | `uploaded`、`mineru_parsing`、`ocr_processing`、`cleaning`、`quality_check`、`understanding`、`indexing`、`ready`、`failed` |
| `reading_route_type` | `fact`、`explain`、`follow_up`、`out_of_scope` |
| `format_review_result` | `compliant`、`non_compliant`、`needs_manual_check`、`not_applicable` |
| `format_review_severity` | `info`、`low`、`medium`、`high` |
| `claim_verdict` | `supported`、`refuted`、`insufficient_evidence`、`conflicting_evidence` |
| `content_type` | `text`、`figure`、`figure_caption`、`table`、`formula`、`metadata`、`reference` |
| `source_type` | `paper`、`standard` |

外部 API 一律使用以上小写值；数据库或工作流内部可以使用不同枚举，但必须在适配层转换。

## 3. 前后端 API 契约

### 3.1 身份与健康检查

| 方法 | 路径 | 请求主体 | 成功响应 | 权限 |
| --- | --- | --- | --- | --- |
| POST | `/auth/register` | `email`、`password`、`display_name` | `AuthView` | 匿名 |
| POST | `/auth/login` | `email`、`password` | `AuthView`，同时写入刷新 Cookie | 匿名 |
| POST | `/auth/refresh` | 无 | 新 `TokenView` | 刷新 Cookie |
| POST | `/auth/logout` | 无 | 空对象，并撤销刷新令牌 | 已登录 |
| GET | `/auth/me` | 无 | `UserView` | 已登录 |
| GET | `/health` | 无 | API、PostgreSQL、Redis、RAGFlow、对象存储状态 | 匿名/运维 |
| GET | `/openapi.json` | 无 | OpenAPI 3 文档 | 开发环境或受控访问 |

`AuthView = { user, token }`；`TokenView` 仅包含短期 `access_token`、`token_type` 和到期时间，不能包含用户论文或配置密钥。

### 3.2 论文与异步入库

| 方法 | 路径 | 请求主体或参数 | 成功响应 | 说明 |
| --- | --- | --- | --- | --- |
| POST | `/papers` | `multipart/form-data`：`files[]` | `PaperUploadBatchView`，HTTP 202 | 创建本地解析与论文理解任务；用户 PDF 不导入知识库。 |
| GET | `/papers` | 分页、状态、关键词 | `PageData<PaperView>` | 仅返回当前用户可见论文。 |
| GET | `/papers/{paper_id}` | 无 | `PaperView` | 包含阶段状态与可问答状态。 |
| GET | `/papers/{paper_id}/file` | `disposition=inline|attachment` | PDF 二进制流 | 需论文访问权限。 |
| GET | `/papers/{paper_id}/sections` | 分页 | `PageData<PaperSectionView>` | 仅展示已完成的结构化章节。 |
| POST | `/papers/{paper_id}/retry` | `stage`：`mineru_parsing|ocr_processing|cleaning|quality_check|understanding`，`force` | `TaskAccepted`，HTTP 202 | 统一重试本地处理与论文理解。 |
| DELETE | `/papers/{paper_id}` | 无 | `TaskAccepted`，HTTP 202 | 异步清理本地对象与结构化产物。 |
| GET | `/tasks/{task_id}` | 无 | `TaskView` | 轮询所有异步任务的统一入口。 |

上传成功后，前端只使用 `paper_id` 与 `task_id` 查询状态。`dataset_id`、`document_id`、`paper_version_id` 和对象存储路径只由后端处理。

当 MinerU、专项 OCR、二次清洗和质量门禁已成功但未配置生成模型时，论文可进入 `ready` 以支持本地证据检索，`understanding.status=unavailable` 且原因为 `MODEL_NOT_CONFIGURED`；问答、总结和格式审查不得返回推测性结果。

### 3.3 阅读会话与论文问答

该组路径严格采用详细设计文档的 `/sessions` 与 `/messages` 命名；`messages` 是问题/回答记录，提交问题不再使用 `/chat` 或 `/questions` 别名。

| 方法 | 路径 | 请求主体或参数 | 成功响应 | 说明 |
| --- | --- | --- | --- | --- |
| POST | `/sessions` | `title?`、`paper_ids` | `ChatSessionView`，HTTP 201 | `paper_ids` 必须全部为当前用户且状态为 `ready`。 |
| GET | `/sessions` | 分页 | `PageData<ChatSessionView>` | 会话列表。 |
| PATCH | `/sessions/{session_id}` | `title` | `ChatSessionView` | 仅修改会话元数据。 |
| GET | `/sessions/{session_id}/messages` | 分页 | `PageData<ChatMessageView>` | 加载消息及其任务状态。 |
| POST | `/sessions/{session_id}/messages` | `question`、`paper_ids?`、`stream` | `TaskAccepted`，HTTP 202 | 启动 `reading_workflow`；只做理解、检索和总结。 |
| GET | `/messages/{message_id}/details` | 无 | `AnswerDetailView` | 返回最终答案、引用、工作流摘要与智能体结果摘要。 |
| POST | `/messages/{message_id}/cancel` | `reason?` | `TaskView` | 取消该问题关联的未完成工作流。 |
| POST | `/messages/{message_id}/feedback` | `feedback_type`、`reason?`、`tags?` | `FeedbackView` | 用户反馈。 |

`POST /sessions/{session_id}/messages` 不接收 `route_type`、`enable_critical_review`、`knowledge_base_id`、`dataset_id` 或 `document_id`。阅读工作流只判断事实、解释、追问或范围外；遇到评价/评分请求时以非评价性论文理解方式回答并给出提示，不进入格式审查或同行评审。

请求与受理结果的最小结构如下：

```json
{
  "question": "这篇论文的方法与实验设置是什么？",
  "paper_ids": ["paper-uuid"],
  "stream": true
}
```

```json
{
  "task_id": "task-uuid",
  "message_id": "message-uuid",
  "status": "pending",
  "status_url": "/api/v1/tasks/task-uuid",
  "stream_url": "/api/v1/messages/message-uuid/events"
}
```

`message_id` 是取消和读取最终答案的资源标识；`task_id` 是任务状态、审计与 SSE 重连标识。两者不得混用。

### 3.4 阅读分析、对比与报告

这些接口沿用同一任务模型，避免把不同模块的后台作业暴露为不同的轮询协议。

| 方法 | 路径 | 请求主体 | 成功响应 |
| --- | --- | --- | --- |
| POST | `/papers/{paper_id}/analyses/{kind}` | `question?`、`force_refresh` | `TaskAccepted` |
| POST | `/paper-comparisons` | `paper_ids`、`dimensions`、`question?` | `TaskAccepted` |
| POST | `/reading-reports` | `paper_ids`、`session_id?`、`template_key`、`title` | `TaskAccepted` |
| GET | `/reading-reports/{report_id}` | 无 | `ReadingReportView` |
| POST | `/reading-reports/{report_id}/exports` | `format`：`markdown|pdf|docx` | `TaskAccepted` |

`summary`、`method`、`experiment` 和论文对比都属于阅读功能：只陈述原文内容及其差异，不产出质量判断、评分或“实验是否充分”的结论。

### 3.5 格式审查

格式审查是独立任务，不复用会话、阅读工作流或自然语言路由。用户只能选择公开的格式规范；RAGFlow 数据集标识、规范检索词和版本映射均由服务端保存。

| 方法 | 路径 | 请求主体或参数 | 成功响应 | 说明 |
| --- | --- | --- | --- | --- |
| GET | `/format-profiles` | 无 | `{ items: FormatProfileView[] }` | 只返回启用的格式规范及其规则，不泄露 RAGFlow 数据集 ID。 |
| POST | `/format-reviews` | `paper_id`、`format_profile_id`、`rule_ids?` | `TaskAccepted`，HTTP 202 | 校验论文归属与规则归属，创建 `format_review` 任务；空 `rule_ids` 表示该规范的全部规则。 |
| GET | `/format-reviews/{format_review_id}` | 无 | `FormatReviewView` | 返回冻结规范版本、汇总和逐规则结果。 |

`FormatReviewView.items[]` 的每项都必须有 `rule_id`、`rule_title`、`result`、`severity`、`finding`、`suggestion?`、`page_numbers`、`paper_evidences` 和 `standard_evidences`。当页边距、字号、行距等视觉信息未被结构化产物提供时，必须返回 `needs_manual_check`，不得猜测为合规或不合规。

### 3.6 管理与可观测性

仅管理员可调用。配置更新带 `If-Match: <version>`，防止覆盖其他管理员的配置。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / PUT | `/admin/model-configs/{id}` | 模型配置与版本快照。 |
| GET / PUT | `/admin/prompt-templates/{id}` | 提示词模板与版本快照。 |
| GET / PUT | `/admin/retrieval-configs/{id}` | RAGFlow 检索配置与版本快照。 |
| GET / POST | `/admin/format-profiles` | 查看或新建格式规范版本；请求体包含服务端 RAGFlow 数据集映射、检索词和规则清单。 |
| GET | `/admin/knowledge-bases`、`/admin/datasets` | 只读查看知识库和导入状态。 |
| GET | `/admin/workflow-runs/{workflow_run_id}` | 审计工作流、证据与事件摘要。 |
| POST | `/admin/evaluation-runs` | 发起离线评测任务。 |
| GET | `/admin/metrics/overview` | 运行、检索、质量与成本指标。 |

## 4. 共享数据模型

| 模型 | 必须跨边界稳定的字段 |
| --- | --- |
| `PaperView` | `paper_id`、`title`、`file_name`、`status`、`parse_progress`、`index_status`、`page_count`、`created_at`、`updated_at`。 |
| `TaskAccepted` | `task_id`、`status`、`status_url`、`resource_id?`、`message_id?`、`stream_url?`。 |
| `TaskView` | `task_id`、`task_type`、`status`、`progress`、`stage`、`resource_id?`、`error?`、各时间戳。 |
| `EvidenceItem` | `evidence_id`、`source_type`、`paper_id?`、`document_id`、`chunk_id`、`content_type`、`quote`、`section_title`、`page_number`、`source_uri`、`retrieval_score`。 |
| `Claim` | `claim_id`、`text`、`verdict`、`confidence`、`evidence_ids`、`reason`。 |
| `AnswerView` | `message_id`、`session_id`、`task_id`、`route_type`、`answer`、`claims`、`evidences`、`warnings`、`is_refusal`、`refusal_reason?`。阅读结果的 `score`、`review_opinions`、`standards` 必须为空。 |
| `FormatProfileView` | `format_profile_id`、`profile_key`、`name`、`version`、`description?`、`rules[]`、`is_active`。不得包含 RAGFlow 数据集 ID 或检索词。 |
| `FormatReviewView` | `format_review_id`、`paper_id`、`format_profile`（键、名称、版本）、`selected_rule_ids`、`status`、`summary_markdown?`、`items[]`、`error?`、时间戳。 |
| `AgentResult` | `agent_name`、`status`、`summary`、`claims`、`evidence_ids`、`warnings`、`metrics`；阅读仅允许 controller、paper_understanding、synthesis 相关结果。 |

`EvidenceItem.quote` 必须是可追溯的原文片段，不能由模型改写。格式审查的 `paper_evidences` 与 `standard_evidences` 只保存本次规则判断实际引用的片段，并保留页码、来源和检索得分。

## 5. SSE 流式契约

流地址由 `TaskAccepted.stream_url` 返回；问答默认形态为 `GET /messages/{message_id}/events?after_sequence={n}`。服务端使用 `text/event-stream`，每条 `data` 为一个 `StreamEvent` JSON。

```json
{
  "event_id": "event-uuid",
  "event_type": "status",
  "task_id": "task-uuid",
  "message_id": "message-uuid",
  "session_id": "session-uuid",
  "sequence": 12,
  "timestamp": "2026-07-19T09:00:00Z",
  "data": {}
}
```

| `event_type` | `data` 最小字段 | 前端行为 |
| --- | --- | --- |
| `status` | `stage`、`label`、`agent_name?` | 更新“路由/检索/理解/汇总”等进度。 |
| `delta` | `delta` | 追加最终答案文本。 |
| `citation` | `evidence` | 增量展示证据卡。 |
| `final` | `answer: AnswerView` | 以完整核验结果替换临时文本。 |
| `error` | `code`、`message`、`retryable` | 停止流并展示统一错误。 |

事件至少一次投递。客户端按 `event_id` 去重、按 `sequence` 排序，并通过 `Last-Event-ID` 与 `after_sequence` 断线续传。`final` 或 `error` 后不再发送业务事件。

## 6. 模块间通信契约

### 6.1 文档入库链路

| 发送方 -> 接收方 | 契约 | 输入摘要 | 输出摘要 | 关键约束 |
| --- | --- | --- | --- | --- |
| paper -> task bus | `PaperIngestRequested` | `task_id`、`paper_id`、`paper_version_id`、对象存储引用、配置版本 | 已入队确认 | 幂等键为 `paper_version_id + parser_version + cleaning_version`。 |
| worker -> parser | `ParsePaperRequest` | 文件引用、解析器版本、`correlation_id` | `ParsePaperResult`：block、媒体对象、页码/bbox、版本 | 不泄露对象存储凭据。 |
| parser -> ocr | `MediaOcrRequest` | `paper_id`、`object_id`、图像哈希、对象类型、页码 | `MediaOcrResult`：文本/表格结构、置信度、引擎版本 | 必需 OCR 失败必须显式失败，禁止静默降级。 |
| parser + ocr -> chunking | `BuildChunksRequest` | 结构块、OCR 结果、清洗版本 | `BuildChunksResult`：Chunk 清单、质量候选 | 必须保留 `source_ref`、页码、对象父子关系与内容哈希。 |
| chunking -> qa_validation | `QualityCheckRequest` | Chunk 清单、质量规则版本 | `QualityReport`：`ready|failed`、阻断项、统计 | 不通过不得进入论文理解阶段。 |
| quality gate -> understanding agent | `UnderstandPaperRequest` | 通过门禁的本地 Chunk、提示词/模型版本 | `PaperUnderstanding`：摘要、事实、缺失信息 | 仅使用本地论文证据；结果持久化在论文记录并返回前端。 |

### 6.2 阅读链路

| 发送方 -> 接收方 | 契约 | 输入摘要 | 输出摘要 | 关键约束 |
| --- | --- | --- | --- | --- |
| chat -> workflow | `StartQaWorkflowCommand(workflow_kind=reading)` | `task_id`、`message_id`、`user_id`、`session_id`、`paper_ids`、原始问题、配置快照 | `WorkflowAccepted` | 服务端校验论文归属和 `ready` 状态。 |
| workflow -> retrieval | `RetrieveEvidenceRequest` | 独立问题、已授权 `paper_ids`、阅读路由、内容偏好 | `EvidenceSet` | 只从本地用户论文 Chunk 获取原文证据。 |
| workflow -> agent | `AgentInvocation` | 任务上下文、已筛选论文证据、提示词/模型版本、输出模式 | `AgentResult` | 只能陈述传入证据支持的论文内容，不调用同行评审 Agent 或 RAGFlow 规范库。 |
| workflow -> qa_validation | `ValidateAnswerRequest` | 候选 `AnswerView`、允许论文证据、阅读路由 | `ValidationResult` | 校验可回答性、引用覆盖、数字一致性、无评分及输出完整性。 |
| workflow -> session / trace | `PersistAnswerCommand` | 已验证答案、工作流摘要、配置快照、审计引用 | `PersistAnswerResult` | 仅 synthesize 成功后一次性提交，避免重试重复写消息。 |

### 6.3 格式审查链路

| 发送方 -> 接收方 | 契约 | 输入摘要 | 输出摘要 | 关键约束 |
| --- | --- | --- | --- | --- |
| format review API -> worker | `FormatReviewRequested` | `task_id`、`format_review_id` | 已入队确认 | 论文、规范和规则集合均已完成权限/归属校验。 |
| worker -> profile snapshot | `FrozenFormatProfile` | 规范键、版本、RAGFlow 数据集、检索词、选中规则 | 固定任务上下文 | 一经提交不再读取可变的当前规范配置。 |
| worker -> RAGFlow | `FormatStandardQuery` | 仅服务端数据集 ID、规则检索词、`top_k` | 规范条文片段 | 只检索该规范映射的数据集；客户端不得传入 dataset/document ID。 |
| worker -> local chunk store | `FormatPaperEvidenceQuery` | 当前论文及版本 | 按章节覆盖的结构化片段 | 只使用本地论文产物；缺失视觉特征必须标注人工核对。 |
| worker -> LLM | `RuleComplianceAssessment` | 明确规则、论文证据 P*、规范证据 S* | 每条规则一个稳定结果 | 禁止评价研究质量、创新性、实验、统计和结论。 |
| worker -> database | `PersistFormatReview` | 汇总、逐规则结论、双侧证据、页码、指标 | `FormatReviewView` | 原子替换同一任务的规则项，保留 profile snapshot 以复现结果。 |

### 6.4 导出、配置与观测

| 发送方 -> 接收方 | 契约 | 说明 |
| --- | --- | --- |
| report -> export worker | `ExportReportRequest` / `ExportReportResult` | 输入是已持久化的报告版本，输出仅返回受控下载 URL 与文件校验信息。 |
| admin config -> workflow / rag / agent | `ConfigurationSnapshot` / `FrozenFormatProfile` | 阅读任务冻结模型、提示词与检索版本；格式审查另外冻结格式规范、规则和 RAGFlow 数据集映射。 |
| 各模块 -> trace | `DomainEvent` | 至少包含 `event_id`、`correlation_id`、`request_id`、资源 ID、阶段、耗时、状态和 `error_code?`。 |

## 7. 错误、权限与兼容规则

### 7.1 必须对前端稳定的错误码

| 错误码 | HTTP | 前端处理 |
| --- | --- | --- |
| `PAPER_NOT_READY` | 409 | 禁止提问，展示当前阶段和任务入口。 |
| `PAPER_ACCESS_DENIED` | 403 | 隐藏资源详情，不重试。 |
| `RAG_NO_EVIDENCE` | 422 | 展示证据不足，不补写外部常识。 |
| `MODEL_OUTPUT_INVALID` | 502 | 展示保守失败或拒答结果。 |
| `REQUEST_TIMEOUT` | 504 | 保留 `message_id`，允许查询最终状态。 |
| `MINERU_PARSE_FAILED` | 502 | 定位到解析阶段重试。 |
| `BAIDU_OCR_SPECIALIZED_FAILED` | 502 | 定位到对象级 OCR 重试。 |
| `CHUNK_QUALITY_FAILED` | 422 | 展示质量报告，不允许进入论文理解。 |
| `QA_EVIDENCE_INVALID` | 422 | 仅显示拒答/不确定性说明。 |
| `FORMAT_PROFILE_NOT_FOUND` | 404 | 刷新格式规范列表，要求重新选择。 |
| `FORMAT_PROFILE_VERSION_EXISTS` | 409 | 管理员应使用新的规范版本，不能覆盖已发布版本。 |
| `FORMAT_RULES_INVALID` | 422 | 高亮不属于所选规范的规则，禁止提交。 |
| `FORMAT_KB_UNAVAILABLE` | 503 | 保留格式审查任务失败状态，提示管理员检查该规范的知识库映射。 |
| `FORMAT_KB_NO_EVIDENCE` | 422 | 提示所选规范库没有可用规则条文。 |
| `FORMAT_PROFILE_SNAPSHOT_INVALID` | 409 | 任务快照不完整，不重试并联系管理员修复规范。 |
| `FORMAT_REVIEW_NO_PAPER_EVIDENCE` | 422 | 提示先重新解析论文或改为人工核对。 |

### 7.2 迁移决议

| 旧调用或歧义 | 统一决议 |
| --- | --- |
| `/chat/sessions` | 统一为详细设计文档的 `/sessions`。 |
| `/chat/sessions/{id}/questions` | 统一为 `POST /sessions/{id}/messages`。 |
| `/workflows/{task_id}/cancel` | 统一为 `POST /messages/{message_id}/cancel`。 |
| `/workflows/{task_id}/events` | 使用受理结果的 `stream_url`；默认为 `/messages/{message_id}/events`。 |
| 前端 `enable_critical_review` / 同行评审入口 | 删除；阅读工作流不产生评价或评分。 |
| 会话或提问中的 `knowledge_base_id` | 删除；阅读只检索当前用户有权访问的本地论文 Chunk。 |
| 客户端传 `dataset_id` / `document_id` | 禁止；格式审查只能提交 `format_profile_id`，由服务端冻结对应 RAGFlow 映射。 |
| `reparse` 与 `reindex` 两个接口 | 统一为 `POST /papers/{paper_id}/retry`，用 `stage` 区分恢复阶段。 |

## 8. 交付与验收

- 后端 OpenAPI 的路径、枚举、包络和错误码必须与本规范一致；前端以生成类型替换临时契约后不得保留旧路径。
- 所有写操作均能用相同 `Idempotency-Key` 安全重试；任务、消息和 SSE 均可通过稳定 ID 关联。
- 前端在 `paper_status != ready` 时不提交阅读或格式审查；阅读页面不显示评分、同行评审或 RAGFlow 规范库入口。
- 格式审查可选择启用的规范和规则，并为每条规则展示合规结果、严重级别、论文证据、规范证据、页码与修改建议。
- 对视觉版式证据缺失的规则，服务端和前端必须稳定使用 `needs_manual_check`，不得把模型推断伪装成自动合规结论。
- 跨模块日志可用 `request_id`、`task_id`、`message_id` 和 `correlation_id` 串联，不记录令牌、密钥或全文。
